# game-climb

- 몽보리 클라임(MongBori Climb). 몽글이와 보리를 기억하며 만든, 버티컬 블라인드의 구슬 체인을 타고 오르는 모바일 게임
- 스마트폰이 기본이고 PC 브라우저에서도 할 수 있다. 홈 화면에 웹 앱으로 설치할 수 있다.
- GP Lab의 `game` 네임스페이스 서비스
- 배포 위치: `Desktop\Lab\game\climb`

## 스택

| 계층 | 기술 |
|---|---|
| 프론트 | TypeScript 5, Vite 5, SVG와 CSS 애니메이션(게임 엔진 없음), Gowun Batang와 Gowun Dodum(Google Fonts) |
| 백엔드 | Express 4, `pg`, `tsx` |
| DB | PostgreSQL 17, DB `gp-lab`, 스키마 `game_climb` |

## 포트

| 계층 | 포트 | 비고 |
|---|---|---|
| 엣지 | `8201` | 게이트웨이가 리스닝 |
| TLS 엣지 | `9201` | 같은 화면의 https. 인증서는 `life/expense`와 같은 `gp-lab.crt` |
| 내부 API | `18201` | Express |
| 개발 서버 | `28201` | Vite dev |

- 규칙: `[계층][네임스페이스][서비스]`, `2`=game, `01`=climb
- 정의 원본: `Desktop\Gateway\nginx\conf\conf.d\00-default.conf`

## 실행

```powershell
.\lab.ps1 api-bg    # 백엔드 :18201 백그라운드
.\lab.ps1 api       # 백엔드 포그라운드(로그 확인)
.\lab.ps1 build     # 프론트 빌드 → frontend\dist
.\lab.ps1 dev       # Vite 개발 서버 :28201(백엔드가 꺼져 있으면 같이 띄움)
.\lab.ps1 stop      # 백엔드 정지
.\lab.ps1 status    # 포트, dist 빌드 시각
```

- 실서비스는 **게이트웨이 필수**. Nginx가 `frontend\dist`를 직접 서빙한다.
- 배포는 `.\lab.ps1 build`뿐이다. 복사 단계가 없고 Nginx 재시작도 필요 없다.

### 이름 규칙

한 자원은 **한 자리, 한 라우터 파일**을 갖는다. 둘의 이름이 늘 맞물린다.
이름은 상위 낱말을 앞에 둔다.

| 자원 | API | 라우터 |
|---|---|---|
| 기록 | `/api/runs` | `routes/runs.ts` |
| 이번 주 랭킹 | `/api/runs/leaderboard` | `routes/runs.ts` |
| 기동 확인 | `/api/health` | `app.ts` |

- 자리 접두사는 `app.ts` 한 곳에서만 붙인다. 라우터 파일 안에서 또 붙이지 않는다.

## 게임

- 새는 날지 않고 버티컬 블라인드의 구슬 체인에 매달려 오른다. 좌우로 끌면(키보드는 ←/→) 몸을 기울여 체인을 흔들고, 체인은 진자처럼 호를 그리며 먼지를 비킨다.
- 체력은 0에서 100까지이고, 오른쪽 위에서 새 얼굴 둘레의 고리로 보인다. 25 아래로 내려가면 고리가 산호색으로 바뀌며 빛난다.
- 먹을 것은 펠렛(+8), 해바라기씨(+15), 국수 생면(+30)이고, 먹을 것 가운데 60%, 30%, 10%로 나온다. 떨어지는 것이 먹을 것일 확률은 잔잔할 때 30%, 가장 거셀 때 22%다. 먼지에 닿으면 20 깎인다. 먼지는 작은 것, 중간, 큰 것이 섞여 떨어지고, 클수록 닿는 범위가 넓다.
- 가끔 화면 위 양옆 중 한쪽에서 무선 청소기가 나와 새 쪽으로 천천히 다가가며 6초 동안 내려온다. 바닥 솔 아래 바람에 들어가면 그쪽으로 끌려가고, 솔에 닿으면 35 깎인다. 지나가는 먼지는 빨아들인다. 처음은 18~25초 뒤, 그다음부터는 25~35초마다이고, 분무기와 겹치지 않는다. 그동안 모터 소리가 낮게 난다.
- 가만히 있어도 비켜 가지 못한다. 새 근처에 2.6초 넘게 아무것도 떨어지지 않으면 다음 것은 새 바로 위로 떨어진다. 넷에 하나꼴로 먹을 것이다.
- 먼지에 맞을수록 머리가 조금씩 잿빛으로 물든다. 다섯 번까지 진해진다.
- 아주 가끔 화면 위 양옆에서 번갈아 분무기를 든 손이 나와 물을 두 번 뿌린다. 그을린 머리가 씻긴다. 머리가 두 번 넘게 그을렸을 때만 오고, 처음은 20~30초 뒤, 그다음부터는 30~45초마다다.
- 창밖은 90초마다 아침, 낮, 오후, 저녁, 밤, 새벽으로 바뀐다(`styles.css`의 `--day`).
- 난이도는 하나다. 40초가 한 마디로, 32초 동안 서서히 빨라지고 8초 동안 잠깐 느려진다. 마디가 거듭될수록 시작점과 꼭대기가 높아진다(`src/game/pace.ts`).
- 기록 테이블의 `difficulty` 컬럼과 API는 그대로 두고, 새 기록은 `normal`로 남긴다.
- 둘의 능력치는 `src/game/characters.ts` 한 곳에 있다.
- 새는 화면 높이의 80% 자리에 매달리고, 흔들면 화면 가로 끝까지 닿는다. 손의 힘은 조금 늦게 실리고, 새는 체인보다 한 박자 늦게 따라 흔들린다.
- 구슬 체인은 마디 열네 개짜리 줄로 셈해 곡선으로 그린다. 위끝과 새가 쥔 자리 사이의 마디가 관성과 무게로 늦게 따라와, 흔들면 가운데가 휘었다가 펴진다.
- 시작하기 전에 READY와 함께 3, 2, 1을 센다. 그동안은 아무것도 떨어지지 않는다.
- 필살기는 먼지만 튕기거나 날린다. 먹을 것은 그대로 먹을 수 있다.
- 배경 음악은 이 게임을 위해 지은 곡을 Web Audio로 그 자리에서 연주한다(`src/audio/bgm.ts`). 음원 파일이나 남의 샘플은 쓰지 않는다. 고르는 화면은 잔잔한 오후(96BPM), 게임 중에는 오르막(112BPM)이고, 화면이 뜨자마자 켜 보고, 브라우저가 첫 손길 전에는 소리를 막으면 처음 누르는 순간 나온다. 오른쪽 위 단추로 끄고 켠다. 먼지에 맞으면 음악이 1.4초 동안 늘어지고 먹먹해졌다가 돌아온다. 그때 두 번에 한 번꼴로 모란앵무가 '삐빅' 운다.
- 효과음도 같은 방식으로 그 자리에서 만든다. 카운트, 시작, 씨앗 먹기, 먼지에 맞기, 쪼기와 튕기기, 날리기, 필살기 다시 쓸 수 있음, 끝, 친구 고르기, 분무기(치익), 청소기(웅)에 소리가 난다.

- 고르는 화면 아래쪽 횃대에 다섯 친구가 일렬로 앉고, 그 아래 맨 밑에 닉네임과 시작 단추가 있다. 고르면 위에 그 친구의 설명이 보이고, 설명 카드 높이는 누구를 골라도 같다. 들어올 때마다 보리가 골라져 있다.
- 필살기는 스페이스나 오른쪽 아래 단추로 쓴다. 모두 1초 동안 가고, 8초마다 다시 쓸 수 있다.

| | 몽글이 | 보리 | 모모 | 번개 | 막둥이 |
|---|---|---|---|---|---|
| 오르기 | 초당 3 | 초당 3.4 | 초당 2.6 | 초당 3.2 | 초당 3 |
| 처음 체력 | 80 | 60 | 100 | 60 | 80 |
| 흔들기 | 작고 정확하게 흔들리고 바로 멈춘다. | 조금 더 크게 흔들리고, 엇박자로 살짝 늦게 먹히고, 끝에 닿으면 튕긴다. | 손이 조금 늦게 실리고 차분하게 멈춘다. | 빠릿빠릿하게 반응하고, 살짝 엇박자에 제멋대로 흔들리지만 보리보다 덜하다. | 고르고 무난하다. |
| 필살기 | 쪼기: 몸 둘레의 막에 닿는 먼지를 쪼아 튕겨 낸다. | 날리기: 날개를 세게 쳐서 화면의 먼지를 모두 날려 버린다. | 유령: 몸이 흐려져 먼지와 청소기가 그냥 지나간다. | 스스슥: 제자리 둘레 좌우 30px 안에서 먼지가 적게 오는 곳으로 날쌔게 오가며 잔상을 남긴다. 그동안 먼지에 맞지 않는다. | 비켜 가기: 둘레에 들어온 먼지가 옆으로 휘어 지나간다. |
| 늘 | | 가까운 해바라기씨를 끌어당긴다. | | | |
| 성격 | 먼지가 다가오면 눈을 동그랗게 뜬다. | 빨리 흔들리면 놀라고 자주 딴청을 피운다. | 이쪽을 잘 보지 않고 놀라지도 서두르지도 않는다. | 이쪽을 자주 보고, 빨리 흔들리면 놀라고, 가끔 두리번거린다. | 순하게 가끔 이쪽을 본다. |

- 모모, 번개, 막둥이 그림은 모란앵무의 얼굴 무늬를 얹어 그린다. 이마가 가장 진하고 목으로 갈수록 옅어진다. 번개는 머리와 얼굴의 경계가 또렷하고 살짝 낮다. 노려보거나 비웃는 듯한 표정은 쓰지 않는다.

## 웹 앱 설치

https로 열어야 설치된다. 이 PC에서는 `localhost`가 안전한 출처라 http여도 된다.
폰이나 다른 기기는 `https://192.168.45.8:9201/`로 들어오고, 그 기기에 사설 CA가 심겨 있어야 한다.
CA를 심는 법은 `..\..\README.md` 6.2 절이다(life/expense와 같은 CA다).

| 기기 | 방법 |
|---|---|
| 안드로이드(Chrome) | 주소창 오른쪽 ⋮ → 홈 화면에 추가 → 설치 |
| iPad, 아이폰(Safari) | 공유 단추 → 홈 화면에 추가 → 추가 |
| Windows, macOS(Chrome) | 주소창 오른쪽의 설치 아이콘, 또는 ⋮ → 전송, 저장, 공유 → 페이지를 앱으로 설치 |
| Windows, macOS(Edge) | 주소창 오른쪽의 설치 아이콘, 또는 ⋯ → 앱 → 이 사이트를 앱으로 설치 |
| macOS(Safari 17 이상) | 파일 → Dock에 추가 |

- 메뉴 이름은 브라우저 판에 따라 조금 다를 수 있다.
- 아이콘 원본은 `public/logo-mark.svg`다. PNG는 그 SVG를 크기별로 찍은 것이다(마스크용과 iOS용은 흰 바탕을 꽉 채운 판).

## 기록과 닉네임

로그인이 없다. 첫 화면에서 닉네임을 적고 시작하면, 판이 끝날 때 그 닉네임으로
기록이 저장된다. 닉네임은 그 브라우저의 `localStorage`에만 남는다.

- 닉네임은 1자부터 20자까지. 백엔드와 DB(`runs_display_name_chk`)가 같은 값으로 막는다.
- 누구나 기록을 남길 수 있다. 랭킹은 닉네임을 글자로만 그린다(`main.ts`의 `leaderboardRow`).
- 로그인을 걷어내기 전의 기록은 가입 때 적은 닉네임으로 채웠다(`sql/2026-10-27_runs_display_name.sql`).
- `users` 테이블과 `runs.user_id`는 아직 남아 있다. 다음 배포에서 지운다(Expand/Contract).

## DB

- 스키마 변경은 `backend\sql\<날짜>_<이름>.sql`과 `_rollback.sql`을 짝으로 둔다.
- `sql\001_init.sql`은 새 환경에서 스키마를 처음부터 세운다. 마이그레이션을 추가하면
  이 파일도 같은 모양으로 고친다.
- `backend\.env`의 `DB_INIT`은 `0`. `1`이면 기동할 때마다 `001_init.sql`이 돈다.

## 환경 변수

- `backend\.env`: `backend\.env.example` 참고
- `frontend\.env`: 지금은 없어도 된다. 포트를 바꿀 때만 `frontend\.env.example`을 참고한다.
- 실제 `.env`는 추적하지 않음

## 브랜치 전략

```
feat/*  →  develop  →  main
```

- 원격: `gentlepotato-lab/game-climb`
- 작업은 `develop`에서 `feat/*`를 따서 하고, 끝나면 `develop`에 머지한다.
- `main`으로의 머지와 전환은 개발이 어느 정도 끝나고 서비스를 시작하기 직전에 한다.
- `build`는 어느 브랜치에서든 한다. 게이트웨이가 작업 트리의 `dist`를 직접 읽으므로
  그때 빌드한 것이 바로 서빙된다.
  - `dist/`는 추적하지 않으므로 브랜치 전환만으로는 실서비스가 바뀌지 않음
